## Paper
GFS goals were to design a distributed file system which has high performance, is reliable, available, scalable. In addition it assumes the following points. 
1. Component failures is a norm rather than exception, therefore monitoring, error detection, fault tolernace and recovery should be built in.
2. Files are huge by traditional standards, multi-GB files are common and system is not designed for billions of KB-sized files.
3. Most files are mutated by appending new data rather than overwriting the existing data. Random writes are almost non-existent, once written files are mostly read sequentially.
4. Designing both the applications and file system API gives Google flexibility and benefits overall design. For example atomic append exists to allow multiple clients to concurrently can append without extra locking mechanism.
