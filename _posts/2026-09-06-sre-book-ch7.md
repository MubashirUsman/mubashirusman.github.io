# Chapter 07 Evolution of Automation at Google

For SREs, the value of automation is what job it does and where it is used. Automation has many benefits and some are under-appreciated. Some of these benefits include:

- __Consistency__ which is not possible when performing the same task manually.

- __Platform__ an automation provides a platform that can be extended, audited and be modified to apply to more systems.

- __Fast Repairs__ it results in knowing the common faults earlier and therefore issues can be fixed than later.

- __Time saving__ is the most cited benefit and it should not be seen in how much effort it saves by not doing it versus how much effort it will take to do automation, instead it should be seen how it will benefit when it can be executed by anyone once automated.

Google is biased to automation because of its scale, their uniform production environment but also because they control the entire stack as they own each and every piece of software they use. Therefore having a platform is a necessity for managing without growing the team in the same proportion.

The use cases of automation at Google are majorly in running and maintaining the systems that run the other software. For example: a cluster turnup and turndown, a software installatin and decomission, rolling out new software.

Heirarchy of automation is important to mention since this is typically the ladder which an organisation goes through: _no automation_ for example database failover manually, _externally maintained and system specific_ a failover script in SRE's home directory, _externally maintained and generic_ an SRE adds a "generic failover" script to be used by everyone, _internally maintained system specific automation_ a database ships with its failover script, _system that do not need automation_ an autonomous system.
